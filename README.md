# ⚡ LIG Sensor Optimizer

Bayesian Optimization platform for **Laser Induced Graphene** sensor fabrication.

Finds the optimal **laser power** and **scanning speed** that minimize electrical
resistance, using as few physical experiments as possible.

---

## Quick Setup (do this once)

```bash
# 1. Make sure Python 3.9+ is installed, then:
pip install streamlit scikit-learn scipy numpy pandas plotly

# 2. Navigate to this folder
cd lig_optimizer

# 3. Launch the app
streamlit run app.py
```

Your browser opens automatically at `http://localhost:8501`.

## How to Use

### Creating a new material

1. Open the sidebar (left panel)
2. Click **➕ New material**
3. Enter a name (e.g. `Polyimide-A`) and the **carbon content %**
4. Click **Create & Start**

### Step 1 — Initial batch (LHS)

Click **🎲 Generate 15 LHS Points**.

You will see a table of 15 `(Power W, Speed mm/min)` combinations.
These are generated by **Latin Hypercube Sampling** on a log-scale
speed axis — this ensures good coverage from very slow (e.g. 10 mm/min)
to very fast (e.g. 40 000 mm/min) speeds.

Take this table to your laser machine and measure resistance for each one.

### Step 2 — Enter resistance values

Come back to the app (it's fine to close and reopen — data is saved after
every entry). You'll see the same table with ⏳ icons for unmeasured rows.

- Enter resistance in **Ohms (Ω)** as read from your multimeter
- You can enter all 15 at once, or enter a few at a time and come back
- Click **💾 Save resistance values** to persist

### Step 3 — Generate BO batch

Once all 15 values are entered, click:

**🤖 Generate Next BO Batch (15 points)**

The system will:
1. Fit a **Gaussian Process** surrogate model (Matern 5/2 kernel, ARD)
2. Apply **transfer learning** from similar materials (if any exist)
3. Run **Kriging Believer** to generate 15 new suggestions that balance
   exploiting the current best region and exploring uncertain areas

Repeat: test → enter → generate → test → enter → generate…

### When to stop

After each batch, the app shows the **improvement %** over the previous batch.

- **< 1% improvement** for 2 consecutive batches → the optimizer has converged
- Typically takes **3–5 batches** (45–75 experiments) to find a good optimum
- Compare with random search which would need 200–500 experiments

### Viewing results

Switch to the **🏆 Results** tab to see:
- Best observed `(Power, Speed)` pair
- GP predicted optimum (may point to an untested but promising region)
- Convergence curve (best R vs experiment number)
- Full experiment table (optimal row highlighted in green)

### Viewing plots

Switch to **📊 Plots** to see:
- **R vs Power** — data sorted by power, line connecting points, star on minimum
- **R vs Speed** — data sorted by speed (log x-axis), star on minimum

Hover over any point to see the full `(Power, Speed, R, Batch)` info.

## Transfer Learning

When starting a **new material**, the optimizer automatically checks for
previous materials in the `data/` folder.

**Similarity** is computed as:

```
w = exp( −|carbon_content_new − carbon_content_old| / 20 )
```

| Carbon content difference | Similarity w | Effect on GP |
|:-------------------------:|:------------:|:-------------|
| 0 %  | 1.00 | Trusted like direct measurements |
| 10 % | 0.61 | Strong transfer |
| 20 % | 0.37 | Moderate transfer |
| 40 % | 0.14 | Weak transfer |
| ≥ 60 % | < 0.05 | Ignored |

Similar material data is incorporated with higher noise, so it nudges
the prior without overriding new measurements.

**Practical effect**: each new material needs fewer LHS points to find a
good starting region. After 5–10 materials, the optimizer may converge
in 2 batches instead of 4.

## Resuming a session

If you close the app mid-session:

1. Reopen with `streamlit run app.py`
2. In the sidebar, select your material from **Switch material**
3. The app will show exactly where you left off:
   - If a batch is partially entered → you'll see the input form with
     completed rows showing ✅ and remaining rows showing ⏳
   - If all current batch entries are done → you'll see the "Generate BO Batch" button

## Technical Details

| Component | Choice | Reason |
|-----------|--------|--------|
| Surrogate model | Gaussian Process | Exact posterior, built-in uncertainty |
| Kernel | Matern 5/2 + ARD | Smooth but finite differentiability; separate length scales let the model learn whether power or speed drives resistance |
| Speed axis | log₁₀ scale | 1–50 000 mm/min spans 4.7 decades; log scale prevents the GP from ignoring low-speed region |
| Resistance target | log(R) then standardised | Handles multiplicative noise from multimeter; stabilises GP optimization |
| Batch strategy | Kriging Believer | Efficient: runs ~15 sequential EI maximizations, each building on the previous virtual observation |
| Acquisition | Expected Improvement (ξ=0.05) | Balanced exploration/exploitation; ξ provides a small bias toward exploration |
| Transfer learning | Per-sample GP alpha | Elegant: dissimilar data gets high noise → low weight on posterior |
| Data storage | JSON files per material | Human-readable, crash-safe, easy to inspect/backup |

## Troubleshooting

**App won't start**
```bash
pip install --upgrade streamlit scikit-learn scipy numpy pandas plotly
```

**"Need at least 2 experiments" error**
You need at least 2 completed resistance measurements before the GP can be fitted.

**BO suggestions cluster at boundary (Power=100, Speed=50000)**
This happens when the simulated/real response surface peaks at the edge of the
parameter range. It's the model telling you the boundary is promising.
If physically implausible, try adjusting the power/speed limits in `bo_engine.py`
(POWER_MAX, SPEED_MAX).

**All suggestions look the same**
Rare numerical edge case. Re-click "Generate BO Batch" — the random restarts
in EI maximization will produce a different result.
